# 设备互联设计（安卓 ↔ 桌面）

> 日期：2026-09-21（同日按用户需求重写）。主题：局域网内**扫码连接**，手机端直接接着编辑桌面端的文件与文件夹。
> 尚属方案阶段，未开工。方案层面的决策已全部收敛，见第 2 节与第 12 节的决策记录。

## 1. 用户要的体验（原始需求，逐条落地）

| # | 用户描述 | 落地为 | 章节 |
| --- | --- | --- | --- |
| 1 | 在局域网内扫码连接电脑端 | 桌面弹二维码，手机应用内扫码，配对一次后记住设备 | §7 |
| 2 | 直接连接电脑上当前窗口已打开的文件 | 手机「设备」页列出桌面**当前聚焦窗口**的标签页，点开即编辑 | §6 |
| 3 | 电脑端设置了文件夹树，安卓端同步这个树 | 共享范围 = 桌面文件树当前根目录（`heid-tree-root`），不额外选一次 | §5 |
| 4 | 安卓端编辑的文件能保存到桌面端 | `write` 命令 + 基线校验；桌面那边没动过就直接落盘 | §5.4 |
| 5 | 桌面端更新了文件夹里的文件，安卓端实时更新 | 桌面递归 watch → 长连接推送变更 → 手机树增量刷新 | §8 |
| 6 | 断网时先存手机、树上提醒、恢复后存回桌面 | 离线写队列 + 树节点状态标记 + 重连回放 | §9 |

硬约束（ROADMAP 的产品定位，本方案必须守住）：约 7 MB 安装包、主包 gzip ≈ 546 KB；
不引入常驻后台（**手动开关，按需启停**，用户已拍板）；无账号、无云中继、不出局域网
（与「明确不做：账号与云同步」不冲突，ROADMAP 措辞已同步更新，见 §11.7）。

## 2. 架构决策

标注 **[用户]** 的是 2026-09-21 两轮确认中由用户拍板的产品行为；标注 **[实现]** 的是纯技术选择，
由实现方决定并在此记录理由，不再回头讨论。

1. **[用户] 拓扑固定：桌面恒为服务端，手机恒为客户端。**
   手机当服务端会被 Android 的 Doze / App Standby 杀后台监听，可靠性不由我们掌控。
   「手机存回桌面」由手机发起写请求实现，不需要手机监听端口。
2. **[实现] 二维码携带地址 → 自动发现可以不做。**
   码里带 `host` + `port` + 一次性配对票，扫码即知去哪连。因此 **UDP 广播发现从必需项降为可选项**，
   顺带避开 Android 组播锁（`MulticastLock`）与各厂商 ROM 的实现差异。这是一处实打实的简化。
3. **[用户] 共享范围直接复用桌面文件树的当前根**（`fileTree.ts:297` 的 `heid-tree-root`），
   符合「电脑端设置了文件夹树，安卓端同步这个树」的直觉，也省掉一次「再选一遍文件夹」的操作。
   桌面没开文件树时，则只暴露当前打开的标签页（§6.3）。
4. **[用户] 根外文件走白名单**：桌面上已打开、但不在共享根内的文件，逐个进白名单暴露给已配对手机。
   理由：用户既然已经在桌面上打开了它，就是愿意看到它；且不必为一个文件扩大整个共享根。
   安全约束见 §6.3（只允许文件本身，不给目录、不给通配）。
5. **[用户] 桌面脏标签不跨设备接管**：手机要接着改，桌面必须先落盘。
   两端永远只有一份「正在改的内容」，杜绝「两边各有一份未保存改动、说不清哪边是对的」这种状态。
   无路径标签（新建未保存）例外——它走 §10 的移交语义，内容随包过去后源端转为只读。
6. **[用户] 版本归属：本功能即 v1.5**（ROADMAP 条目 42 / 43 / 44）。
   原计划的 v1.5（条目 40 平台决策 + 41 移动端收尾）经 2026-09-21 复核后降级为 **v1.4.1 补丁**——
   那两项没有主题，是 v1.4 触屏适配没收干净的尾巴，按「补丁版随修随发」处理。
   其中「行号槽触屏适配」经实测**不属收尾**，已从 v1.4.1 移出暂挂候选：
   `CodeEditor.tsx:543-695` 的 153 行全部挂在 mouse 事件系上（一个 pointer 事件都没有），
   仅解除 `:1498` 的门控则拖动多选不会工作（v1.4 的 CSV 批次已实证 WebView 拖拽不发 `mousemove`），
   而迁到 pointer 事件系会动到桌面路径，与「桌面零回归」约束冲突。详见 ROADMAP 的 v1.4.1 小节。
7. **[用户] 手动开关**：设置面板一个「设备互联」总开关。打开才 bind 端口、才建 watch；关闭立即全部释放。
8. **[实现] 传输加密在第一阶段（阶段 0）就做，不留到后面补。**
   方案：XChaCha20-Poly1305（`chacha20poly1305`，纯 Rust）+ 配对票经 HKDF 派生会话密钥。
   192-bit 随机 nonce 天然规避重放计数器同步；**无证书生命周期管理**，代码量最小。
   不选 rustls 自签（`rustls` 虽已随 `ureq` 的默认 tls 特性进入依赖树，见 `Cargo.toml:24`，
   但需新增 `rcgen` 并管证书持久化与过期，对「轻量」定位不划算）。
   必须前置的理由：事后加加密要动整个帧协议与所有命令的编解码路径。
9. **[实现] 离线队列用 IndexedDB，不用 localStorage。**
   它承载「用户以为已经存好了」这份信任，容量不能是瓶颈；localStorage 有 5MB 量级的悬崖，
   而草稿（`drafts.ts:16`）的 2MB 上限纪律在这里不可接受。项目内此前无 IndexedDB 先例，
   需自建一个极薄的封装并配测试。
10. **[实现] 实时推送用既有长连接**（同一条 TCP），不额外开 WebSocket —— 帧协议已能承载服务端主动推送。

## 4. 传输与协议

### 4.1 承载

- TCP，`std::net::TcpListener` / `TcpStream`——**零新增网络框架依赖**。
  accept 循环与阻塞读写放 `tauri::async_runtime::spawn_blocking`（同 `http.rs:95`）。
- 帧：`u32 大端长度前缀 + UTF-8 JSON body`。二进制内容走 base64（`base64` crate 已在依赖里）。
- **双向**：客户端请求（带自增 `id` 关联响应）+ 服务端主动推送（`id` 为空，`method` 为 `event`）。
  §8 的实时变更、§6 的桌面标签页变化都走推送通道。
- 心跳 `ping`/`pong` 15s，两次失败判定断连 → 手机端进入离线态（§9）。
- `hello` 里带协议版本，不匹配直接拒绝并提示升级——安卓侧载无静默更新（README:128），
  两端版本会长期不一致，这条不是可选项。

### 4.2 命令集

```
hello      {protocolVersion, deviceName, platform, appVersion, credential}
                                             → {ok, rootAvailable, rootName} | {needPair}
list       {relDir}                          → [{name, isDir, size?}]
stat       {relPath}                         → {size, mtimeMs, isDir, hash}
read       {relPath, forceEncoding?}         → {text, encoding, bom, eol, binary, mtimeMs, hash}
write      {relPath, text, encoding, bom, eol, baseHash, baseMtimeMs}
                                             → {ok, hash, mtimeMs} | {conflict, serverText, serverHash, serverMtimeMs}
tabs                                       → [{relPath|null, title, language, dirty, mdView, cursor}]
tabOpen    {index}                           → {text, encoding, bom, eol, relPath|null, hash}
transfer   {tabs: TransferredTab[]}          → {ok}                  # 反向：手机把未保存内容推给桌面
ping                                         → {ok}

# 服务端推送（无 id）
event {type:'fs',      changes:[{relPath, kind:'create'|'modify'|'remove'|'rename', oldRelPath?}]}
event {type:'tabs'}                                              # 桌面标签页变了，请重新 tabs
event {type:'rootChanged', rootName}                             # 桌面换了文件树根目录
event {type:'linkClosed', reason}
```

服务端**不重写文件逻辑**：`read` 调 `encoding::detect_and_decode`，`write` 调既有写盘路径，
`stat.size` 复用 `large_file::file_size`。网络层只是这些函数的一层外壳。
手机端因此拿到与桌面**完全一致**的编码/BOM/换行/二进制判定，
不必退回 `fileIO.ts:144-147` 那条 JS 启发式检测的降级路径。

### 4.3 暴露范围与路径逃逸防护（安全关键）

- 允许访问的只有两类：**共享根目录内**的相对路径，以及**桌面当前打开的标签页**（§6.3 的白名单）。
- 协议里只有 `relPath`，**不接受绝对路径**。服务端解析后 `canonicalize`，校验仍以根为前缀，否则拒绝。
  需防：`..` 穿越、Windows 盘符切换（`C:` → `D:`）、UNC 路径、symlink 指向外部。
- 这一层**先写测试再写实现**，是本方案唯一「写错就等于把整个磁盘暴露给局域网」的地方。
  与 ROADMAP v2.0 条目 46（fs 权限从 `path:"**"` 收窄）方向一致，可视为其前置工作。

## 5. 文件夹树同步与文件读写

### 5.1 远程路径表示

`tab.path` 是全仓的身份键（`readLocalPath` / `writeLocalPath` / `fileSize` / `displayNameFromPath` /
`dirNameOf` / `draftKeyForTab`（`drafts.ts:29-31`）/ `addRecentFile` 全以它为准）。远程文件用：

```
hide-remote://<deviceId>/<percent-encoded 相对共享根的路径>
```

用 deviceId 而非 IP 入键——换网、DHCP 重新分配 IP 后，已打开的标签仍指向同一台设备。

### 5.2 改动清单

- `src/lib/platform.ts`：`displayNameFromPath` / `dirNameOf` 加 `hide-remote://` 分支。
- `src/lib/fileIO.ts`：`readLocalPath` / `writeLocalPath` / `saveFileToDisk` 各加远程分支。
  远程标签**保存不走 SAF 新建文档**，直接写回桌面；只有「另存为」才落到手机本地。
- `src/lib/largeFile.ts`：`fileSize` / `classifyBySize` 远程分支。
- `src/lib/fileTree.ts`：新增 `remoteDirLister: DirLister`（`chooseRoot` 返回共享根、`list` 走 `list` 命令、
  `displayName` 显示「设备名 · 根目录名」）；`watch` 不由 lister 实现——实时性走 §8 的推送通道。
- `src/components/FileTreeSidebar.tsx`：根来源增加「远程设备」一档。**v1 保持单根**（根的*类型*可变），
  不改造成多根树。
- `src-tauri/src/link.rs`（新增）：协议编解码、服务端监听与推送、客户端连接、配对与设备白名单。
- 设置面板：总开关、端口、二维码入口、已配对设备（可解除）、本机 IP（供手填兜底）、
  **当前共享范围明示**（「手机端可访问：`D:\projects\notes`」——用户必须看得见暴露了什么）。

### 5.3 能力边界（如实标注）

- **大文件不远程打开**：`large_file` 的分块读取是 `#[cfg(desktop)]`（`lib.rs:199-207`），
  远程分块预览要另设窗口协议。v1：`stat` 超 32MB 直接拒绝并说明原因。
- **跨文件搜索不含远程**（`search_in_dir` 同为 desktop-only，rayon 不进 APK）。
- **手机端系统级操作置灰**（在资源管理器中显示 / 复制 / 剪切），与 SAF 树的既有降级一致（v1.4 有先例）。

### 5.4 保存与冲突

1. `read` 时记下 `hash` + `mtimeMs` 作为基线，随标签走。
2. `write` 带基线；服务端比对磁盘当前状态，一致才写。
3. 不一致 → 返回 `conflict` + 服务端最新内容 → 前端走既有 **diff 时间线**逐条采纳。
4. 不做自动三方合并。

## 6. 桌面「当前窗口已打开的文件」

### 6.1 「当前窗口」的定义

桌面是多窗口的（标签可拖出成窗，`win-*`）。服务端是**进程级单例**（一个端口，状态放 Tauri `State`），
但标签页状态活在**各窗口的前端**里。因此：

- 每个窗口把自己的标签列表上报到 Rust `State`（含 `relPath`、title、dirty、language、mdView、光标）。
- Rust 侧跟踪哪个窗口当前聚焦（Tauri 焦点事件），`tabs` 命令返回**聚焦窗口**的那一份。
- 桌面切换聚焦窗口 / 开关标签 / 存盘 → 推送 `event {type:'tabs'}`，手机端刷新列表。

### 6.2 手机端呈现

手机端呈现为一个「设备」页，顶部一块「电脑上正打开的」列表（不属于文件树，语义不同：
这些是**标签页**，其中可能有还没保存、甚至还没有路径的）。点开：

- **有路径且在共享根内** → 直接以 `hide-remote://` 标签打开，走 §5 的读写通道。
- **有路径但在根外** → 走 §6.3 的白名单，同样以 `hide-remote://` 打开。
- **脏标签（桌面改了还没保存）** → **不接管**。列表里显示为「桌面上有未保存的修改」并置灰，
  提示先在电脑上保存。这是 §2 决策 5：两端永远只有一份「正在改的内容」，
  杜绝「两边各有一份未保存改动、说不清哪边是对的」。
- **无路径标签**（新建未保存） → 走 §10 的移交语义：内容随包传到手机成为手机的未保存标签，
  桌面端该标签转为只读「已移交」态。这不是「同时持有两份」，是所有权转移。

### 6.3 根外文件的白名单（§2 决策 4）

桌面打开的文件可能不在共享根内（如根是 `D:\projects\notes`，但同时开着 `C:\Users\...\todo.md`）。
处理：**当前打开的标签页逐个进白名单**——用户既然已经在桌面上打开了它，
把它暴露给已配对的手机符合其意图，且不必为一个文件扩大整个共享根。

约束（安全关键，与 §4.3 同级）：

- 白名单条目是**具体文件的规范化绝对路径**，不给目录、不给通配、不给前缀匹配。
- 每次 `read` / `write` / `stat` 都重新 `canonicalize` 入参并校验「等于白名单里的某一条」，
  防止拿到白名单文件的句柄后借相对路径跳出去。
- 标签页关闭即从白名单移除（推送 `event {type:'tabs'}` 时同步收敛）。
- symlink 解析后若指向白名单外，拒绝。


## 7. 扫码配对

### 7.1 流程

1. 桌面：设置 →「设备互联」→ 打开开关（首次要选/确认共享范围）→ 点「让手机连接」→ 弹二维码。
2. 二维码内容：`hide-link://pair?host=<ip>&port=<port>&ticket=<一次性票>&name=<设备名>`。
   票 2 分钟有效、用一次即废。
3. 手机：H.I.D.E 内「扫一扫」→ 解析 → `hello` 带票 → **桌面弹确认框**（「允许 <手机名> 访问
   `D:\projects\notes` ？」，TOFU）→ 用户点允许 → 双方各自存长期凭证。
4. 之后**不需要再扫**：手机记住 host + 凭证，启动即尝试重连；连不上（IP 变了）才提示重新扫码。

### 7.2 权限与体积（必须如实说明）

- 系统相机不识别自定义 scheme，扫码必须在**应用内**做 → 需要 `CAMERA` 权限
  （`AndroidManifest.xml` 现仅有 `INTERNET`，`:3`）+ 解码库（纯 JS 的 jsQR 一类）。
  这是本方案唯一的新权限，也是唯一的新前端依赖。
- 对策：解码库走**懒加载 chunk**（与 mermaid / katex / js-yaml 同策略，`README:241` 的先例），
  不进主包；二维码**生成**在桌面端，同样懒加载。
- 首次点「扫一扫」才申请相机权限，不在启动时申请。

### 7.3 兜底：手输配对码

二维码下面同时显示 6 位数字码。相机坏了、权限被拒、或屏幕反光扫不出来时，手机手输即可。
零权限零依赖，成本极低，**必须保留**。

### 7.4 手填 IP（调试与最后兜底）

设置面板显示本机 IP 与端口。这层同时是开发期的调试通道，一直保留。

> 因为二维码已携带地址，**UDP 广播自动发现降级为可选增强**（原方案 §7.3 已删）。
> 若将来要做，用「手机 UDP 广播 + 桌面单播回应」，避开组播锁。

## 8. 实时更新（桌面 → 手机）

用户明确要求：「桌面端更新了什么文件在文件夹里的话，安卓端也能够实时更新」。

### 8.1 服务端

- 开关打开且有已配对设备在线时，对共享根建**一次**递归监听。
  **必须用 `watchImmediate`**（`fileTree.ts:273-281` 的诊断注释：`watch()` 会硬编码注入
  `delayMs=2000` 走 notify-debouncer-full，其 `watch()` 在主线程同步扫全树建缓存，
  7.7 万文件目录实测冻结 4.7~8.5s）。去抖在 JS/Rust 侧自己做。
- 事件过滤：复用 `search.rs:227` 的 `is_skipped_dir`（`node_modules` / `.git` / `target` / `dist` / …）
  与 symlink 跳过（`:440-464`）。**不过滤会被构建产物的抖动刷爆链路**——一次 `npm install`
  就能产生上万条事件。
- 去抖 300ms（与 `useExternalFileWatcher.ts:27` 的 `WATCH_DEBOUNCE_MS` 同值），合并成一批推送。
- 无已配对设备在线时**不建监听**（守住「不引入常驻后台」）。

### 8.2 手机端

- 收到 `event {type:'fs'}` → 按 relPath 定位受影响的目录，只对**当前已展开**的目录做增量更新
  （既有树是懒加载的：展开才列子项，`README:76`）。未展开的目录打个「有变化」的惰性标记，展开时重列。
- **手机正打开的文件被桌面改了** → 走既有外部修改检测流程（`useExternalFileWatcher` 的语义 +
  `diffTimeline` 的 UI），提示「桌面上的这个文件已更新」并逐条采纳。
  若手机侧该文件有未推送的本地修改 → 直接进 §9 的冲突态，不自动覆盖。
- 桌面换了文件树根 → `event {type:'rootChanged'}` → 手机端提示并刷新。

### 8.3 诚实的边界

「实时」= 事件推送级别（秒内），不是文件系统级的强一致。断连期间桌面的变更不会补推——
重连后手机端对已展开目录做一次全量重列来收敛（比做增量补偿日志简单得多，也够用）。

## 9. 离线暂存与恢复（用户明确要求的重点）

场景：手机在编辑桌面上的文件，WiFi 断了 / 电脑休眠了 / 走出信号范围。要求是「东西先存在手机上，
文件夹树有对应提醒，连接恢复后可以继续保存回桌面端」。

### 9.1 离线写队列

- 保存动作失败（断连）时**不丢内容**：写入本地队列，标签页保持脏状态，状态栏提示
  「已离线保存到手机，等待同步」。
- 队列条目：`{relPath, content, encoding, bom, eol, baseHash, baseMtimeMs, queuedAt, attempts}`。
  `baseHash` / `baseMtimeMs` 是**最初读到时的基线**，不是上一次尝试写入时的——这是冲突判定正确的前提。
- 同一文件多次离线编辑 → **折叠为一条**：内容取最新，基线保持最初那份。
  否则回放时会拿中间态去比对，产生假冲突。
- 持久化：**IndexedDB**（§2 决策 9），随应用重启存活（进程被杀也不丢）。
  项目内无先例，需自建一个极薄封装 + 测试；不用 localStorage 是因为它有 5MB 量级的悬崖，
  而这里承载的是「用户以为已经存好了」的信任。
- 容量纪律：真写满或写入失败时**明确告警**而非静默放弃——`drafts.ts:71` 的静默跳过
  （超限即 return false）在这里不可接受。告警文案要说清「这一份没能存进手机，请复制到别处」。

### 9.2 文件树状态标记

沿用既有小圆点语言（`FileTreeSidebar.tsx:646` 的 `bg-amber-500` 脏点），扩展为一组状态：

| 状态 | 含义 | 视觉 |
| --- | --- | --- |
| 已同步 | 与桌面一致 | 无标记 |
| 待同步 | 本地有未推送的修改，等连接恢复 | 橙色圆点 + 上行箭头 |
| 冲突 | 本地改了，桌面**也**改了，需要人决定 | 红色圆点，点击进 diff 时间线 |
| 桌面已更新 | 桌面改了，本地没有未推送修改 | 蓝色圆点，点击重读 |
| 离线 | 链路断开 | 树顶部横幅「已断开连接 · N 项待同步」+ 重连按钮 |

全部要有中英双语文案（`i18n.ts` 中文表为 key 源、英文表同构，编译期对齐）与触屏长按菜单等价物。

### 9.3 重连回放

1. 链路恢复 → 按 `queuedAt` 顺序逐条回放。
2. 每条先 `stat` 取桌面当前 `hash` / `mtimeMs`，与条目的**基线**比对：
   - 一致 → `write` 落盘，标记清除，推送给桌面让它重读（桌面若正开着这个文件，
     走它自己的外部修改检测）。
   - 不一致 → 桌面在这期间改过 → 转**冲突态**，拉取桌面最新内容，进 diff 时间线由用户逐条采纳。
     **不自动覆盖任何一边。**
3. 回放期间 UI 显示进度，可取消。失败条目保留在队列里，`attempts` 递增。

### 9.4 必须对用户讲清的一件事

「网络恢复就可以继续保存回桌面」在**桌面那边没动过这个文件**时是全自动的。
但如果断连期间桌面上也改了同一个文件，就不存在安全的自动答案——两边都是有效修改，
程序替用户选哪一边都可能毁掉工作。这种情况会明确标红并弹 diff 让用户挑。
这不是实现不到位，是这个问题本身的性质。文案上要写成「有 N 处需要你确认」而不是「同步失败」。

## 10. 未保存内容的跨设备移交

针对桌面上**还没有路径**的标签页（新建未保存的文件），以及手机 → 桌面方向。

`SessionTab` 增加第三个变体（`session.ts:15-17` 现为 `file` / `virtual`）：

```ts
| { kind: 'transferred'; title: string; content: string; language: string;
    mdView?: SessionMdView; encoding?: string; eol?: LineEnding;
    cursor?: { line: number; col: number } }
```

- 接收端落地为**无路径标签**（`path = null`），可直接编辑，另存为时走本地 SAF / dialog。
- `restoreSessionTabs`（`sessionRestore.ts:38`）加一个分支——它已经在处理 `virtual` 的
  「草稿叠加并标脏」，`transferred` 是同一形状。
- 光标位置经既有 `jumpRequest`（`tabModel.ts:64-66`）承载。滚动位置不带。
- 单条上限沿用 `MAX_DRAFT_CHARS = 2_000_000`（`drafts.ts:16`），超限拒绝并提示先保存。
- **移交语义，不是同步**：发出后源端该标签进入「已移交」态（只读 + 状态栏标记 +「已移交至 \<设备\>」），
  保留基线内容。反向移交回来时用 diff 时间线呈现差异。
- 入口：桌面标签右键菜单 + 菜单「发送到设备…」；手机标签长按菜单。
  触屏目标 ≥48dp，hover 样式包进 `@media (hover:hover) and (pointer:fine)`（v1.4 的既有规范）。

## 11. 风险与待验证项

1. **Windows 防火墙**：首次 bind 会弹「允许访问」框。用户点「取消」则功能静默失效。
   必须给可诊断的错误提示（不是笼统的「连接失败」）+ 文档说明怎么放行。
   **这大概是后期最吃支持成本的一项。**
2. **release APK 的明文流量开关（必须实测，不许推理）**：`build.gradle.kts:31` 设
   `manifestPlaceholders["usesCleartextTraffic"] = "false"`（debug 才是 `true`，`:50`），
   `AndroidManifest.xml:11` 引用该占位符。该策略由 Java 网络栈与 WebView 强制，
   Rust 侧原生 socket **大概率不受约束**——但这是推理。必须用 **release 签名包在真机**验证 TCP 能连通，
   否则就是「模拟器上通、用户手上全挂」，与 v1.4.0 图标事件同一类坑
   （见 `feedback-mobile-release-branding-assets`）。
3. **模拟器 NAT**：x86_64 模拟器访问宿主机要用 `10.0.2.2`，真机用局域网 IP。
   验链路建议直接上真机 ARM 平板；在模拟器上反复重试后误判为代码 bug 是已知陷阱
   （见 `android-emulator-on-this-machine`）。
4. **watch 的性能与噪声**：共享根若是大型工程目录（含 `node_modules` / `target`），
   递归监听的建立成本与事件量都需要实测。§8.1 的 `watchImmediate` + `is_skipped_dir`
   是必要前提，不是优化项。
5. **多窗口**：监听与端口是进程级单例；标签页上报按窗口，`tabs` 返回聚焦窗口那份。
   互联 UI v1 只在主窗口提供，避免子窗口抢同一份状态。
6. **换网 / 休眠 / 端口被占**：WiFi 切 5G、笔记本合盖、端口被占，都要有明确状态与手动重连入口，
   不能静默假死。§9 的离线态是这条的兜底。
7. **ROADMAP 措辞冲突（已解决）**：「明确不做」原含「账号与云同步」，与本方案看着自相矛盾。
   实际不违背（无账号、无云、不出局域网），且 2026-09-21 已在 ROADMAP「明确不做」补上边界段落，
   把「局域网设备直连」明确划入「做」的一侧，并指向本稿第 15 节的「明确不做」清单。
8. **离线队列是全新的持久化子系统**，且承载「用户以为已经存好了」的信任。
   它的测试密度要求应高于本方案其他部分：进程被杀、存储写满、回放途中再次断连、
   同文件并发编辑、基线折叠逻辑，都要有测试。

### 12.1 仍待确认（不阻塞开工，实施到对应阶段前定即可）

1. **多台手机能否同时配对**：建议允许配对多台、但同一时刻只服务一台（第二台连接时提示
   「已有设备连接中」）。并发多客户端会让 §9 的冲突矩阵成倍复杂，收益不明。
2. **开关状态是否跨重启记忆**：建议**不记忆**，每次启动都是关的。
   与「不引入常驻后台」一致，也避免用户忘了自己开着共享。代价是每次要手动开一下。
3. **默认端口号**：取一个不常用值（如 47123），需在设置里可改，并在被占用时明确报错而非静默失败。
4. **设备名来源**：桌面用机器名，手机用 `Build.MODEL`？还是都允许用户改？
   影响配对确认框与树根显示名（§5.2 的「设备名 · 根目录名」）的可读性。
5. **二维码里是否带设备指纹**：带上可让手机端在扫码时就校验对端身份（防同网段抢答），
   但会让码内容变长、密度变高。倾向带。

## 14. 验收标准

每阶段都要过：

- **单元测试**：帧编解码、**路径逃逸防护**（`..` / 盘符切换 / UNC / symlink，测试先行）、
  `hide-remote://` 编解码往返、watch 事件过滤与去抖、离线队列的基线折叠与回放决策矩阵、
  `transferred` 变体存取、协议版本不匹配的拒绝路径。照现有惯例（vitest + `#[cfg(test)]`）。
- **实测**：真机 ARM 平板 + 桌面同网段跑通完整链路；**release 签名包单独再验一遍**（§11.2）；
  断网/恢复用真实关 WiFi 验，不用代码模拟。
- **体积核算**：主 bundle gzip 增量 < 20 KB（扫码库必须懒加载）；安装包增量 < 300 KB。超了要说明或改懒加载。
- **桌面零回归**：开关关闭时桌面行为与当前版本逐字一致（v1.4 的同款约束）。
- **触屏规范**：新增触点 ≥48dp，hover 收进媒体查询，长按菜单等价物齐备（desktop-to-android 技能）。
- **双语**：所有新文案中英齐备（`i18n.ts` 编译期对齐机制）。

## 15. 明确不做

- 实时协同编辑（CRDT / OT）、多光标同步、两端同时编辑同一份未保存内容。
- 账号体系、云中继、跨公网穿透（内网穿透 / NAT 打洞 / 转发服务器）。
- 手机当服务端（Doze 杀连接，可靠性不可控）。
- 远程大文件分块预览、远程跨文件搜索（desktop-only 的 Rust 模块不进 APK）。
- 自动三方合并（一律走 diff 时间线由用户逐条采纳）。
- 断连期间桌面变更的增量补偿日志（重连后对已展开目录全量重列收敛）。
