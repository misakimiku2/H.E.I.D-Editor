# H.I.D.E v1.4.1 发行说明

> 发布日期：2026-09-21 · 标签：`v1.4.1` · 补丁版（随修随发）

## 主题：v1.4 触屏适配收尾

v1.4.0 把安卓做成了「能用」，但有两处没收干净。这一版就是那两个尾巴，
外加把「只支持 Windows 与安卓」这件事从路线图里的决策变成 README 上写给用户的一句话。

安卓两处：

- **Markdown 表格的行列增删**：点选单元格浮出的工具条自 v1.1.0 就在，但按钮只有 32px 高，
  低于 v1.4 自己定的 ≥44dp 触屏档，而且从来没量过、没有测试。现在整条定宽 240dp、
  四个动作（行+ / 行− / 列+ / 列−）各 58–62×44dp。
  落点也换了做法：原来按「点击那一刻单元格的位置」浮在格子上方，而键盘是异步弹起来的——
  IME 把预览区压矮的那一刻，工具条会被推到键盘底下，等于按钮消失（平板实测复现）。
  现在钉在屏幕底缘、键盘之上（`--heid-kb` + 12dp），不用测量也不会被推走，
  顺带落进了拇指热区。表头是唯一行 / 唯一列时点「−」不再白标一次脏。
- **SVG 元素位置微调**：检查面板属性页新增**位移 X/Y** 两行，读写元素的前导 `translate`
  （拖拽与方向键改的正是这一段），两侧配 ± 步进按钮，一步 1 个 SVG 用户单位，
  与桌面方向键的默认档同值。
  两轴都归零时把 `transform` 属性整个删掉，源码里不留 `translate(0 0)` 这种噪声；
  改动仍以最小补丁写回，注释、缩进、同行其他属性逐字保留。
  触屏用户此前只能靠手指拖，想挪准 1 个单位做不到。

桌面端只有检查面板多出的那两行（X/Y 输入框与 ± 步进在桌面同样可见，比只敲方向键更直观），
其余界面与交互零改动。

## 平台支持范围（这版写进 README）

H.I.D.E 只出 **Windows 10/11** 与 **Android 7.0+** 两个平台的包，**不做 macOS 版、不做 Linux 版**。
这是定下来的结论，不是「还没排上期」：把「秒开、约 7 MB、够用」做深，比多挂两条平台线更值钱。
macOS 要付费开发者证书 + 公证才过得了 Gatekeeper；Linux 的 WebView 是 WebKitGTK，
而非本项目全程验证所在的 Blink/Chromium 内核——两条线各要一套发布链路加一整套界面重验。
逐条依据记在 [docs/ROADMAP.md](docs/ROADMAP.md) 条目 40。

## 已知限制（本版未覆盖）

- **源码编辑器的行号槽**（点选整行、拖动多选、悬停提示）在安卓整体关闭：那 153 行交互全挂在
  mouse 事件上，迁到 pointer 会动到桌面路径，与「桌面零回归」冲突；等 v1.5 设备互联落地、
  看清平板上的真实用法再估。
- **源码行内的取色圆点 11.9×11.9dp**：点开取色器的唯一入口，平板上极难命中。
  本版实测时才发现并记入路线图，未及修改。
- **平板标签页关闭按钮 28×28**：嵌在标签内部，扩到 48dp 会与相邻标签命中区重叠；
  替代路径是长按标签出菜单关闭（已归入「明确不做」，属有意妥协而非待补的缺口）。
- **打印 / 导出 PDF 在安卓无入口**（WebView 无系统打印对话框），可用系统分享或桌面端打印。
- **外部修改检测 / 文件监听**安卓不做（SAF 无真实路径），文件被别处改过需重新打开。

## 验证

- 单元测试 828 → **855 例全绿**（71 个测试文件），`tsc` 干净，前端构建通过。
  表格工具条此前零测试，本版补 10 例（四个动作的源码结果、未提交值不丢字、无可删项不空改动、
  浮层停靠位置）；`svgWrite` 的前导 translate 读写补 10 例；SVG 工作台补 7 例。
- 平板模拟器实测（1280×800 · 系统字体 1.3× · 真 touch 事件 + WebView CDP 量取 `getBoundingClientRect`）：
  整屏 touch-target 审计下本版新改的两处界面 **0 项 <44dp**；键盘报 368dp 时表格工具条底边落在
  420dp（键盘之上、视口之内），实点「行+」表格由 2 行变 3 行；SVG 检查面板 ± 各 44×44、
  X/Y 输入框 68×44、面板 244dp 宽无横向溢出；把 X 改成 5 后源码为 `transform="translate(5 2)"`，
  同行 `x="10" y="10"` 与上方注释逐字保留。
- 桌面回归：表格工具条本就由 `IS_ANDROID_APP` 门控，桌面仍走悬停边线的 +/− 单按钮；
  检查面板新增的那两行为纯增量，画布与方向键的代码一字未动
  （`composeTranslate` 只把内联正则提成与 `readTranslate` 共用的常量，其行为测试全绿）。
  桌面未做真机逐项复核，依据是上述代码路径与 855 例测试。
