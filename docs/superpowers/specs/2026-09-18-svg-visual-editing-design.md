# SVG 可视化编辑 — 设计文档

日期：2026-09-18
状态：已与需求方逐节确认

## 背景与目标

H.I.D.E 目前的 `.svg` 工作台（`SvgWorkbench.tsx`）是「左源码 + 右预览」：预览经 blob URL 以 `<img>` 渲染（脚本不执行，天然安全），支持缩放平移，但**预览只是看的，改内容仍然要回源码里手敲**。需求方常编辑 AI 生成的 SVG 插画（源码带中文结构注释），希望能在画布上直接选中元素、改颜色/描边/文本、拖动位置——即从「预览」升级为「轻量可视化编辑」。

产品定位约束：本项目是轻量文本编辑器。SVG 编辑做的是「微调 AI 生成图的工作视图」，**不是要做 Inkscape**：不做路径锚点编辑、不画新图形。

## 需求清单（已确认）

| 项 | 结论 |
|---|---|
| 第一版深度 | 轻量微调：点选元素 + 属性面板（fill/stroke/粗细/透明度/文本）+ 拖拽移动 + 结构树 + 调色板全局换色 + PNG 导出 |
| 写回策略 | 方案 B「手术式写回」：解析时记录每个元素的源码区间，修改只替换该元素的文本；注释/缩进/未触碰部分逐字保留 |
| 选中模型 | 单选（不做多选） |
| 提交时机 | 拖拽过程只改渲染 DOM，松手才提交一次文本补丁 |
| 触屏 | 用 pointer events 保证基本可用，第一版不做专门触屏适配（后续按 android 移植流程单独过） |
| 降级 | XML 解析失败 / 扫描器与 DOM 对不齐 → 自动退回现有纯预览模式 |

## 非目标（v1 明确不做）

- path 锚点级编辑、钢笔/形状绘制工具
- 多选、成组/解组、图层重排（结构树 v1 只读导航 + 点选联动）
- 对齐吸附、智能参考线（方向键微调即可）
- `<style>` 内 CSS 类颜色的收集与替换（调色板 v1 只看 fill/stroke/stop-color 的属性与内联 style）
- 专门的触屏人机工学适配

## 一、数据流与核心不变量

**编辑器文本（`tab.content`）仍是唯一事实源。** 所有可视化编辑最终都化为「替换某段源码文本」，走与手敲完全相同的链路：

```
tab.content（SVG 源码）
   │ svgParse(content)                ← 解析 + 记录每个元素的源码区间
   ▼
{ dom: Document, spans: Element[] }  ← dom 为权威树（未 sanitize）
   │ svgSanitize(dom)                ← 仅渲染副本：剥脚本/事件/外链，盖章结构索引
   ▼
SvgCanvas 内联渲染（可交互）
   │ 用户操作（属性面板 / 拖拽 / 删除）
   ▼
svgWrite：在权威树上改 → serializeToString(该元素) → 替换其源码区间
   → 新文本 → updateTabContent()
```

因此撤销/重做（文本级）、脏标记、保存、草稿、外部修改检测、多标签同步**零新增接线**，全部复用现状。每次松手/面板提交 = 一条撤销历史，粒度够用。

关键正确性点（两棵树的分工）：

- **权威树**（未 sanitize 的 DOMParser 结果）承担一切修改与序列化——保证写回源码不丢 sanitize 剥掉的东西；
- **渲染副本**（sanitize 后的克隆）只用于显示与命中测试，永远不回写；
- sanitize 时给渲染副本的每个存活元素盖 `data-hed-idx="<权威树先序索引>"`，画布选中事件凭 idx 回到权威树对应节点，规避「sanitize 删节点导致两树索引错位」。

## 二、模块划分

沿用「lib 纯函数 + 组件」的既有模式（对标 `csv.ts` + `CsvGridEditor.tsx`）：

| 模块 | 职责 |
|---|---|
| `src/lib/svgParse.ts` | 轻量 XML 扫描器：带位置追踪地扫一遍标签流，栈式配对产出每个元素的 `[start, end)` 区间（先序）；同时用 `DOMParser`（MIME `image/svg+xml`，严格 XML）建权威树；两棵序列按先序 zip。计数对不上 → 返回可编辑否决，调用方降级纯预览 |
| `src/lib/svgSanitize.ts` | 深拷贝权威树 → 移除 `<script>`、`on*` 事件属性、`javascript:` URL、指向外部的 `href/xlink:href`（`data:` 与同文档 `#id` 保留）、`<foreignObject>`；给存活元素盖 `data-hed-idx`。**只处理渲染副本，从不触碰源码文本** |
| `src/lib/svgWrite.ts` | `serializeToString(元素)` → 区间替换；多个补丁按区间从后往前套用保持偏移有效；删除元素后若留下全空白行则整行吞掉 |
| `src/lib/svgPalette.ts` | 扫描 fill / stroke / stop-color（属性 + 内联 style），按颜色汇总使用处；全局换色 = 逐元素补丁（后往前批量套用） |
| `src/components/SvgCanvas.tsx` | 内联渲染渲染副本；hover 轮廓、点击选中（选中框按 `getBBox`）、拖拽移动（过程只改副本，pointerup 提交）、空白处拖拽 = 平移画布（沿用现状） |
| `src/components/SvgInspector.tsx` | 右侧面板，三个 tab：**属性**（fill/stroke/stroke-width/opacity，`<text>` 无子元素时可编辑文本内容）、**图层**（只读结构树，与画布选中双向联动，显示标签名 + id/class 线索）、**颜色**（调色板 + 全局换色）；底部导出 PNG（1x/2x/4x）与复制为 PNG |
| `src/components/SvgWorkbench.tsx` | 升级为编排者：`svgEdit` 关 = 现状纯预览（完全不变）；`svgEdit` 开 = 画布 + 面板；解析失败/编辑不可用时面板禁用并退回预览 |

### svgParse 要点

- 扫描器须正确跳过：XML 声明、DOCTYPE、注释、CDATA、处理指令；属性值内允许出现 `>`、引号、换行。
- 自闭合 `<rect/>` 与 `<rect></rect>` 都产出完整区间；区间按先序排列且互不交叉（严格嵌套）。
- zip 对齐的性质测试：所有元素区间切片按序拼接 + 区间外碎片拼回 == 原文逐字节相等；元素计数 == 权威树元素计数。
- 典型 AI 生成 SVG（几百 KB 内）单次解析毫秒级；沿用现有 180ms 停顿防抖，编辑提交后的重解析走同一条管线，无性能问题。

## 三、视图状态与布局

- 页签新增 `svgEdit?: boolean`（默认 `false`），随会话持久化——模式对标 markdown 的 `mdView` / CSV 的 `csvView`。
- 工作台预览区右上角「编辑 / 预览」切换按钮（lucide 图标，i18n 文案走 `i18n.ts`）。
- 编辑模式布局：预览区右侧伸出 260–280px 面板（同现有 zinc 深/浅色体系，可折叠）；手机 stacked 模式下面板堆叠在画布下方。
- 画布现有能力全部保留：滚轮以光标为锚缩放、空白拖拽平移、双击适应/原始尺寸、棋盘格透明底、右下角缩放工具条。
- 光标语义：空白 = grab（平移），元素 = default，拖元素 = moving。

## 四、交互细节

- **选中**：点击画布元素选中（属性面板同步填充），Esc 取消，点击空白取消；选中框为覆盖 `getBBox` 的描边矩形（随画布缩放，线宽按 `1/scale` 补偿保持视觉恒定）。
- **拖拽移动**：pointerdown 在元素上 → 拖动 = 移动元素（副本上实时 `transform: translate(dx/scale, dy/scale)`，除以当前画布缩放保证手速一致）；pointerup 提交——在权威树上更新/合成该元素 `transform` 属性 → 序列化 → 区间替换。元素已有 `transform` 则在前面合成 translate，不破坏原有变换。
- **方向键微调**：选中后方向键按 1 个 SVG 用户单位（viewBox 坐标系，Shift × 10）平移，每次按键 = 一次提交（按住连发即多条历史，可接受）。
- **删除**：Delete/Backspace 删除选中元素（区间替换实现，含空白行清理）；根 `<svg>` 元素不可删。
- **属性面板**：数值/颜色输入即在权威树上改 → 提交；颜色控件复用现有 `ColorPickerPopover`（自制零依赖取色器浮层，onChange 回调写回，与代码内颜色圆点同一套交互）；所有字段的占位显示「继承/未设置」，修改即写入显式属性。
- **文本编辑**：仅 `<text>` 且无子元素时开放 textarea；有 `<tspan>` 子元素的文本，选中 tspan 本身即可编辑其文本。
- **调色板**：列出文档内所有用到的颜色（色块 + 使用次数 + 点击反选出使用元素）；点色块换色 = 全局替换该颜色的所有 fill/stroke/stop-color 出现处（单条文本提交，一步撤销）。
- **导出 PNG**：sanitize 副本序列化 → blob → `Image` → 离屏 canvas 按倍率绘制 → Tauri dialog 存盘 / clipboard 插件复制；透明背景。
- **撤销**：Ctrl+Z 即编辑器文本撤销，与手敲无差别。

## 五、安全模型（不倒退）

- 现有「`<img>` blob 渲染、脚本不执行」的安全性质，在内联渲染后由 sanitize 层等价承接：脚本不执行、无内联事件、无 `javascript:` URL、无外部网络请求（外链 image/use 一律剥离，仅留 `data:` 与 `#id`）。
- sanitize 只作用于内存中的渲染副本；源码编辑器内容与磁盘文件永不因 sanitize 改动——用户源码里的 `<script>` 原样保留（用户看得见、可自行删除，只是画布上不渲染执行）。
- 非 well-formed XML：`DOMParser` 报错 → 编辑模式禁用，退回纯预览（现状的 invalid 占位）。

## 六、测试

重点全部压在 lib 纯函数（vitest，同 `fileTree.test.ts` / `csv` 的模式）：

- `svgParse`：区间正确性（嵌套/自闭合/注释/CDATA/XML 声明/属性含 `>` 与换行）；「全区间切片 + 碎片拼回 == 原文」性质测试；zip 计数一致性；畸形 XML → 明确否决。
- `svgWrite`：单元素替换后其余部分逐字节不变；多补丁从后往前套用；删除后空白行清理；连续两次编辑幂等（spans 随新文本重算）。
- `svgPalette`：颜色收集（属性/内联 style/stop-color，大小写与 rgb() 形式）；全局替换的补丁正确性。
- `svgSanitize`：剥离清单逐项断言；`data-hed-idx` 与权威树先序一致；合法内容（`data:` 图片、`#id` 引用）不被误伤。
- 组件层：轻量冒烟（渲染不崩、面板随选中填充），不做重量级交互测试（交互逻辑尽量下沉到 lib）。

## 七、分期

- **M1 回写链路立起来**：svgParse/svgWrite + 降级路径 + 画布点选 + 属性面板（颜色/描边/透明度/文本）+ 删除。验收：改一个 rect 的 fill，源码只有那一处变了，注释原样。
- **M2 空间操作**：拖拽移动 + 方向键微调 + 图层结构树。
- **M3 周边增强**：调色板全局换色 + PNG 导出/复制。

每期独立可用、可发布；M1 落地后即使后两期缓行，产品价值已成立（点选改色优于手敲坐标）。
